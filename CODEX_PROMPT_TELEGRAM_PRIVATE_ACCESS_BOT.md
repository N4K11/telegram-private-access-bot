## 1. Важные ограничения Telegram и платежей

1. Telegram Stars — основной способ оплаты для цифрового доступа внутри Telegram.
2. Crypto Pay должен быть опциональным модулем через feature flag.
3. Не смешивай Stars и Crypto Pay в одну грязную логику.
4. Если Telegram Bot API не позволяет сделать какую-то функцию напрямую, не имитируй её фейково. Сделай рабочий альтернативный UX.
5. Не обещай автоматическое получение списка всех каналов, где бот админ, если Bot API этого не даёт. Реализуй:
   - ручное добавление channel_id или @username;
   - автоматическое обнаружение через события, где это возможно;
   - проверку прав бота в канале.
6. Для выдачи доступа используй invite-ссылки, созданные ботом.
7. Для исключения пользователя после окончания подписки используй безопасную стратегию:
   - banChatMember для удаления;
   - затем unbanChatMember, если нужно, чтобы пользователь мог купить доступ снова.

## 5. Функционал пользователя

Пользовательский бот должен уметь:

1. `/start` всегда отправляет новое главное сообщение, а не редактирует старое.
2. Все дальнейшее взаимодействие после `/start` идёт через inline-кнопки и редактирование одного текущего меню.
3. В каждом разделе должны быть кнопки:
   - Назад;
   - Главное меню.
4. Пользователь видит:
   - статус подписки;
   - дату окончания доступа;
   - список тарифов;
   - способы оплаты;
   - историю покупок;
   - поддержку;
   - кнопку повторно получить ссылку, если подписка активна.
5. После успешной оплаты бот должен:
   - создать персональную invite-ссылку;
   - записать покупку в БД;
   - активировать или продлить подписку;
   - отправить понятное сообщение;
   - сохранить payment id/charge id.
6. Если подписка активна, новая покупка должна продлевать срок, а не перезаписывать дату окончания некорректно.
7. Заблокированный пользователь не должен иметь возможность покупать или получать ссылку.

## 6. Каналы и доступ

Реализуй управление каналами:

1. Бот может работать с одним или несколькими приватными каналами.
2. Админ может добавить канал через:
   - `@username`, если применимо;
   - `chat_id`;
   - пересланное сообщение из канала, если это работает в текущих ограничениях Telegram.
3. Бот проверяет, что он админ канала.
4. Бот проверяет права:
   - invite users;
   - ban/restrict users.
5. Для каждого тарифа можно выбрать канал.
6. Для доступа создавать персональные invite-ссылки:
   - `member_limit=1`, если применимо;
   - короткий срок жизни ссылки, например 24 часа;
   - хранить ссылку в БД;
   - уметь повторно выдать ссылку активному пользователю.
7. При окончании подписки бот удаляет пользователя из канала.
8. Если пользователь уже вышел сам — worker не должен падать.
9. Все ошибки Telegram API логировать и обрабатывать безопасно.

## 7. Telegram Stars

Telegram Stars — основной способ оплаты.

Реализуй:

1. Создание invoice через Telegram Bot API.
2. Валюта: `XTR`.
3. `provider_token` для Stars должен быть пустым, если так требует актуальная документация Telegram.
4. Обработка:
   - `pre_checkout_query`;
   - `successful_payment`.
5. Таблица payments должна хранить:
   - user_id;
   - tariff_id;
   - amount;
   - currency;
   - provider;
   - telegram_payment_charge_id;
   - provider_payment_charge_id;
   - invoice_payload;
   - raw_payload;
   - paid_at;
   - status.
6. Обязательная идемпотентность:
   - один и тот же successful_payment не должен продлевать подписку дважды.
7. Реализуй `/paysupport`.
8. Подготовь сервисный метод для возврата Stars через `refundStarPayment`, если актуальный Bot API это поддерживает.
9. В админке добавь платежную историю пользователя.

## 8. Crypto Pay как опциональный модуль

Crypto Pay должен быть отдельным модулем, включаемым через:

```env
CRYPTO_PAY_ENABLED=true
```

Если `CRYPTO_PAY_ENABLED=false`, бот должен полностью работать без Crypto Pay.

Реализуй:

1. Отдельный сервис `crypto_pay.py`.
2. Отдельную таблицу `crypto_invoices`.
3. Создание invoice.
4. Сохранение invoice_id.
5. Проверку статуса invoice.
6. Webhook handler, если задан `PUBLIC_WEBHOOK_URL`.
7. Fallback reconciliation worker, который периодически проверяет неоплаченные invoice.
8. Идемпотентность crypto-платежей.
9. Поддержку минимум TON/USDT, если это позволяет актуальная версия Crypto Pay API.
10. Понятную ошибку пользователю, если Crypto Pay отключён.

## 10. Тарифы

Админ должен уметь:

1. Создать тариф.
2. Изменить название.
3. Изменить цену в Stars.
4. Изменить цену для Crypto Pay, если crypto включена.
5. Изменить длительность.
6. Выбрать канал.
7. Включить/выключить тариф.
8. Изменить сортировку.
9. Архивировать тариф.

Требования:

1. Не удалять физически тариф, если по нему были покупки.

3. Валидация:
   - цена > 0;
   - длительность > 0;
   - канал существует;
   - бот имеет права в канале;
   - название не пустое.

2. Все кнопки должны вести в существующие обработчики.
